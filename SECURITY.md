# Security Policy

## Supported version

Security fixes target the current public client on `main`.

## Reporting a vulnerability

Do **not** publish secrets, API keys, private endpoints, customer data or detailed exploit information in a public issue.

If GitHub private vulnerability reporting is available in the repository's **Security** tab, use it.

If it is not available, open a minimal public issue requesting a private contact channel without disclosing sensitive details.

The public client repository must not contain private owner-side logic, administrative credentials or confidential operational data.
